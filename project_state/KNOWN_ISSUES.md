# Known Issues

- **`npm run lint` is env-blocked.** The TS import-resolver's native addon (`unrs-resolver`) fails with `ERR_DLOPEN_FAILED` on this machine (Node-ABI / missing MSVC runtime), not a code defect. `npm run typecheck` and `npm run test` run green. Run lint on a healthy toolchain. (`typecheck`/`test` were verified this session.)
- **Fix-it state is process-memory only.** The Fix-it loop uses in-memory adapters (`app/lib/agents/adapters`), so previewed/applied/undone actions, the audit trail, and budget counters live in the Node process — lost on restart, single-instance only. The Prisma/Redis adapters at M0.T7 make them durable and multi-instance behind the same ports.
- **Fix executor is simulated (no live Shopify write yet).** `SimulatedFixExecutor` drafts and records the intended reversible change; it does not call the Admin API and undo is a no-op reversal. The real Shopify write/read executor (which needs findings enriched with affected product refs) swaps into the same `ExecutorPort`/`DiffPort` at M1.T4. The full pipeline (policy, locking, optimistic concurrency, audit, undo bookkeeping) is real.
- **Entitlement plan/role are pre-launch defaults.** `resolveEntitlements` returns real granted scopes from the session but a fixed `GROWTH` plan and `OWNER` role until Billing (M1) and team management land. Fixes are therefore gated by scope + these defaults, not real billing.
- **AI provider live path unexercised.** `app/lib/ai` (M0.T9) is unit-tested with fakes, but no real model call has run — this env has no provider keys. Set a key in `.env` to exercise it. The `fetch`-based OpenAI-compatible adapters (OpenAI, **Qwen**, **Hugging Face**) and the Google (Gemini) adapter have not been validated against their live endpoints — model IDs, base URLs (Qwen intl vs China host), and HF chat/streaming support per model may need adjustment on first real call. The **cheap tier now routes to Qwen `qwen-turbo`** (docs/16 tiering): set `QWEN_API_KEY` to use it, else cheap-tier calls fail over to Claude primary. Added dependency: `@anthropic-ai/sdk`. MCP tool exposure deferred to M1.T4.
- **Copilot is stateless + grounds by re-scanning per turn.** The Copilot (M1.T8) keeps threads only in the browser tab (no persistence) and re-runs a bounded live quick scan on every message to ground the reply — an extra Admin GraphQL read per turn. Its AAC budget (`InMemoryCopilotBudget`) is a separate process-memory meter, not yet unified with the fix pipeline's budget. Persisted threads, cached-scan grounding, and a single durable per-shop budget all land with M0.T7/M1.T5. The Copilot also exposes **no write/read tools to the model yet** (grounding is injected, not tool-called); tool exposure + inline `action_offer`/`ActionPreview` cards land with the tool catalog (M1.T4).
- **DB is still SQLite.** Anything requiring persistence (scan history, durable findings/actions, billing, chat threads, audit rows) is blocked on the M0.T7 cutover.
- **Quick scan is interactive, not cached.** The dashboard runs a bounded (≤50 product) live Admin GraphQL read on load and on "Run scan". The queued background scan with cached snapshots + "as of" freshness (docs/14, docs/17) supersedes it at M1.T5/M0.T8. For very large catalogs it samples, framed honestly in the UI.
- **Public landing placeholder.** `app/routes/_index/route.tsx` still has template copy ("A short heading about [your app]"). Cosmetic; replace when marketing copy is finalized.
- **GDPR compliance webhooks implemented (M1.T12), audit is log-only until DB.** The three mandatory topics (`customers/data_request`, `customers/redact`, `shop/redact`) are enabled in `shopify.app.toml` and handled (HMAC-verified, retry-on-500). `shop/redact` deletes the shop's `Session` rows; the `customers/*` handlers hold no customer PII to act on yet and gain real logic when customer-scoped tables land (docs/18). The compliance audit trail is currently structured logs (docs/41) — durable audit rows land with the M0.T7 cutover. Live delivery/HMAC unverified in this env (`npm run dev`/deploy needed).
