# Known Issues

- **`npm run lint` is env-blocked.** The TS import-resolver's native addon (`unrs-resolver`) fails with `ERR_DLOPEN_FAILED` on this machine (Node-ABI / missing MSVC runtime), not a code defect. `npm run typecheck` and `npm run test` run green. Run lint on a healthy toolchain. (`typecheck`/`test` were verified this session.)
- **Fix-it state is process-memory only.** The Fix-it loop uses in-memory adapters (`app/lib/agents/adapters`), so previewed/applied/undone actions, the audit trail, and budget counters live in the Node process — lost on restart, single-instance only. The Prisma/Redis adapters at M0.T7 make them durable and multi-instance behind the same ports.
- **Fix executor is simulated (no live Shopify write yet).** `SimulatedFixExecutor` drafts and records the intended reversible change; it does not call the Admin API and undo is a no-op reversal. The real Shopify write/read executor (which needs findings enriched with affected product refs) swaps into the same `ExecutorPort`/`DiffPort` at M1.T4. The full pipeline (policy, locking, optimistic concurrency, audit, undo bookkeeping) is real.
- **Entitlement plan/role are pre-launch defaults.** `resolveEntitlements` returns real granted scopes from the session but a fixed `GROWTH` plan and `OWNER` role until Billing (M1) and team management land. Fixes are therefore gated by scope + these defaults, not real billing.
- **AI provider live path unexercised.** `app/lib/ai` (M0.T9) is unit-tested with a fake provider, but no real model call has run — this env has no `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`. Set a key in `.env` to exercise it. The OpenAI adapter (`fetch`-based Chat Completions) has not been validated against the live endpoint; MCP tool exposure is deferred to M1.T4. Added dependency: `@anthropic-ai/sdk`.
- **DB is still SQLite.** Anything requiring persistence (scan history, durable findings/actions, billing, chat, audit rows) is blocked on the M0.T7 cutover.
- **Quick scan is interactive, not cached.** The dashboard runs a bounded (≤50 product) live Admin GraphQL read on load and on "Run scan". The queued background scan with cached snapshots + "as of" freshness (docs/14, docs/17) supersedes it at M1.T5/M0.T8. For very large catalogs it samples, framed honestly in the UI.
- **Public landing placeholder.** `app/routes/_index/route.tsx` still has template copy ("A short heading about [your app]"). Cosmetic; replace when marketing copy is finalized.
- **GDPR compliance webhooks commented out** in `shopify.app.toml` — launch-blocking, scheduled M1.T12 (docs/24/43).
